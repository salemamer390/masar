# المرحلة 7 — تشغيل الرواتب والتكلفة

**الحالة:** منفذة جزئيًا — دورة المسير الأساسية والواجهة مرتبطة بقاعدة البيانات.
**التاريخ:** 7 أكتوبر 2026

## المنفذ

- نموذج `PayrollRun` وخدمة `PayrollRunService` لدورة: `Draft → Approved → Locked`.
- إنشاء سجلات الرواتب من هيكل الراتب النشط وحفظ لقطة إعدادات الحساب ولقطة نتيجة كل موظف.
- منع إعادة توليد مسير معتمد أو مقفل، وقفل سجلاته مع `is_locked`.
- migration `2026_10_07_004000_link_records_to_payroll_runs` لربط السجلات بالمسير وفهرستها.
- واجهة الرواتب تعرض الشهر المختار، الملخصات الفعلية، قائمة المسيرات، عدد سجلات كل مسير، وأزرار الاعتماد أو القفل وفق الصلاحية.
- رابط مباشر إلى صفحة **إعدادات الحساب** للمستخدم صاحب صلاحية `payroll.settings`.
- عند التوليد، تُستهلك فقط سجلات الحضور المعتمدة: دقائق الإضافي، أيام الغياب، والإجازات المعتمدة (كسجل تتبع). كما تُستهلك الجزاءات المغلقة خلال الشهر. تُحفظ معرفات كل مصدر وقيمه في `calculation_snapshot` حتى تظل نتيجة المسير قابلة للمراجعة بعد تغير البيانات.
- أضيفت صلاحيتان منفصلتان: `payroll.approve` لاعتماد المسير و`payroll.lock` لقفله؛ ولا تستخدم الواجهة أو المسارات صلاحية التحرير العامة لهاتين العمليتين.

## المسارات

- `POST /payroll/runs/generate`
- `POST /payroll/runs/{payrollRun}/approve`
- `POST /payroll/runs/{payrollRun}/lock`

## التحقق

- فحص PHP لـ `PayrollController` ناجح.
- لا توجد هياكل رواتب نشطة في قاعدة البيانات الحالية، لذلك لم يُنشأ مسير تجريبي على بيانات حية.

## المتبقي قبل الإطلاق

- إدخال الغياب والإجازات والإضافي والجزاءات المعتمدة فقط في الحساب.
- Adjustment Run مستقل بدل أي تعديل لسجل مقفل.
- فصل صلاحية الاعتماد عن صلاحية القفل في مصفوفة الصلاحيات النهائية.

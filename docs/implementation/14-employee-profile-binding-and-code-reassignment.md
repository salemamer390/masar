**النطاق:** بيانات ملف الموظف وعلاقاتها فقط. لم يتم تعديل جداول أو سجلات الرواتب أو التأمينات أو الضرائب.

## نتيجة إعادة ترقيم الأكواد

تم تنفيذ الترحيل `2026_10_07_009000_reassign_employee_codes_and_create_profile_details.php` داخل transaction وبقيم مؤقتة قبل التعيين النهائي، لمنع أي تعارض مع unique constraint.

لم تتغير `employees.id` أو `salaries.id` أو أي سجل داخل payroll / salaries / insurance / tax.

## Field mapping

| واجهة الملف | Model | المصدر |
| --- | --- | --- |
| الكود، الأسماء، الهوية، الهاتف، البريد، النوع، الميلاد، العنوان، الحالة الاجتماعية، المؤهل | `Employee` | `employees` |
| القسم، الوظيفة، الفرع، نوع التوظيف، الحالة، المدير المباشر | `Employee` وعلاقات `belongsTo` | FK في `employees` إلى master data / employees |

| الجنسية، البريد الشخصي، نمط وأيام وساعات العمل، العقد والتجربة والإجازة والعملة والهوية والموقف العسكري والشروط | `EmployeeProfileDetail` | `employee_profile_details` (علاقة one-to-one) |

| الراتب والتأمين والحضور والإجازات والجزاءات والحركات | العلاقات الموجودة | جداولها التشغيلية الأصلية، للقراءة فقط في الملف |

## الإصلاحات

- أُضيفت علاقة `profileDetail` وتم تحميلها في `EmployeeController@show`.
- أُضيف نموذج تعديل شامل لملف الموظف؛ يحفظ حقول `employees` و`employee_profile_details` معًا داخل transaction ويسجل before/after في Audit Log.
- حقول master data تستخدم IDs في الحفظ (`department_id`, `job_id`, `branch_id`, `employment_type_id`, `status_id`, `manager_employee_id`) وتعرض الاسم فقط.
- أُضيف validation لتواريخ العقد والهوية، البريد، الرقم القومي، وربط المدير؛ ولا يمكن للموظف أن يصبح مدير نفسه.

## الحقول التي لم تكن مرتبطة سابقًا

لم يكن هناك مخزن منظم أو واجهة حفظ للبيانات التالية: الجنسية، البريد الشخصي، نمط/أيام/ساعات العمل، نوع العقد، فترة التجربة، الإجازة السنوية، حالة إرفاق العقد، العملة، بيانات إصدار الهوية، الموقف العسكري، والشروط الإضافية. تم توفير مخزن one-to-one واضح لها بدل وضعها في `notes`.

## الحقول ذات المصدر القائم

- المدير المباشر: علاقة `employees.manager_employee_id`، وليس نصًا مكررًا.
- مقر العمل: `employees.branch_id → branches`.
- البنك وطريقة الصرف: `employee_bank_accounts` بعلاقات FK، وليس حقول نصية داخل الموظف.
- المستندات: `documents`، وليس حالة ثابتة في الواجهة.
